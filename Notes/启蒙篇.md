# 后端启蒙篇

## Part 1 开发环境

我用 Java，IDE 是 IDEA，系统是 Linux。

先写了一个普通 Java 程序：

~~~java
public static void main(String[] args) {
    System.out.println("Hello World From Terminal!");
}
~~~

运行以后终端正常输出：

Hello World From Terminal!

![terminal](../images/hello-terminal.png)

然后用 Spring Boot 写了一个很简单的接口：

~~~java
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello World From Web Application!";
    }
}
~~~

启动以后访问：

http://localhost:8080/hello

浏览器正常显示：

Hello World From Web Application!

![web](../images/hello-web.png)

访问 /hello 时 Spring 会找到对应的 hello() 方法，然后把返回的字符串发给浏览器。

# Part 2 后端常用技术栈

## 1. MySQL

### MySQL 能存多少数据？

这个没有一个固定数字。

几百万、几千万行数据对 MySQL 来说都很常见，再大的数据也可以存，具体能扛多少还是和表怎么设计、索引、机器配置这些有关系。

所以学校几万用户、几十万篇笔记这种量对 MySQL 来说并不算大。

### 为什么 MySQL 数据很多的时候还能查得比较快？

一个很重要的东西是索引。

如果没有索引，查一条数据有时候就要扫很多行。

有索引以后，MySQL 可以先通过索引定位数据，不需要每次都把整张表从头到尾找一遍。

InnoDB 常见的索引结构是 B+ Tree。

另外 MySQL 还有查询优化器、Buffer Pool 这些东西，不是每次查询都直接傻读磁盘。

### Java 怎么操作 MySQL？

最底层可以直接用 JDBC。

实际 Spring Boot 项目里一般会在 JDBC 上面再用一层东西，比如 MyBatis、MyBatis-Plus、Spring Data JPA。

我之前主要用过 MyBatis-Plus。

大概就是 Java 代码发查询或者修改请求，MySQL 执行以后再把结果交回 Java。

## 2. Redis

### Redis 为什么快？

最主要的一点是数据主要放在内存里。

内存访问比直接从磁盘读快很多。

Redis 本身的数据结构和实现也比较适合做高频读写，所以经常拿来做缓存。

不过 Redis 快不代表所有数据都应该塞 Redis，真正的数据一般还是会落到 MySQL 这种数据库里。

### MySQL 的一行数据怎么放到 Redis？

比如 MySQL 里有一个用户：

id = 1  
name = zookie  
age = 20

可以用：

user:1

作为 key。

value 可以直接存成 JSON：

~~~json
{
  "id": 1,
  "name": "zookie",
  "age": 20
}
~~~

也可以用 Redis Hash 分字段存。

查 user 1 的时候可以先查 Redis，Redis 没有再去 MySQL 查，然后把结果放进 Redis。

真正做项目的时候还要考虑缓存过期和数据库更新以后缓存怎么处理，不然两边数据可能不一致。

### Java 怎么操作 Redis？

Spring Boot 里可以用 Spring Data Redis。

常见底层客户端有 Lettuce、Jedis。

实际写的时候可以通过 RedisTemplate 之类的东西操作 Redis。

## 3. RabbitMQ

### 除了耗时任务，还有什么情况会用 MQ？

MQ 不只是为了“先返回，之后慢慢处理”。

我现在感觉它另一个很重要的作用是把不同功能拆开。

比如一篇笔记创建完成以后，可以先发一条消息。

搜索索引、消息通知、AI 总结这些功能谁需要就自己消费这条消息，不需要让保存笔记的代码直接一个个调用它们。

请求突然很多的时候也可以先堆在 MQ 里，消费者按自己的速度处理，避免一瞬间把后面的服务压死。

### Java 怎么向 RabbitMQ 发消息和收消息？

Spring Boot 里可以用 Spring AMQP。

发送消息可以用 RabbitTemplate。

接收消息可以用 @RabbitListener。

大概就是生产者把消息发进 RabbitMQ，RabbitMQ 保存和转发，消费者再把消息取出来处理。

## 4. AI Agent

### Agent 为什么可以做除了聊天以外的事情？

LLM 本身并不能直接操作电脑。

Agent 会给模型接上 Tool。

比如：

- 读文件
- 改文件
- 执行终端命令
- 搜索网页
- 调 API

模型判断下一步要调用什么 Tool，Tool 真正执行，然后把结果再交给模型。

所以我现在对 Agent 的理解差不多就是：

LLM + Tool + 一套不断执行任务的流程。

### 长期使用 Agent，很多信息怎么保存？

不能把所有信息一直塞在 Context 里，因为上下文是有限的。

长期信息可以放到数据库、文件或者其他外部存储里。

需要的时候再搜索出相关内容放回当前 Context。

如果内容很多，还可以把文本转成向量放进向量数据库，用语义相似度找相关内容。

所以长期记忆和模型当前这一次能看到的 Context 不是一个东西。

# Part 3 其他基础知识

## 1. HTTP 请求和响应

### HTTP 请求有哪些部分？

我现在主要分成：

- 请求行
- 请求头
- 请求体

请求行里会有请求方法、路径、HTTP 版本。

请求头里会放一些额外信息，比如 Content-Type、Authorization、Cookie。

请求体里可以放真正提交的数据。

### HTTP 响应有哪些部分？

主要是：

- 状态行
- 响应头
- 响应体

状态行里会有状态码。

响应体就是服务器真正返回的数据，比如 JSON。

### 提交一篇新的长笔记用 GET 还是 POST？

用 POST。

这是向服务器提交一份新的数据，而且长篇笔记可以放在请求体里面。

GET 更适合获取数据，不应该拿 GET 去创建一篇新笔记。

### 常见状态码

200：请求正常完成。

201：创建成功，比如成功创建一篇笔记。

400：请求本身有问题，比如参数格式不对。

401：没有登录或者认证失败。

403：已经知道是谁，但是没有权限。

404：东西不存在，比如查一个不存在的笔记。

409：发生冲突，比如用户名已经被注册。

500：服务器自己出问题了。

## 2. API

如果要设计一个“获取某篇笔记详细内容”的接口，我至少会考虑这些东西：

请求方法可以用 GET。

路径可以设计成：

GET /api/notes/{id}

id 就是哪一篇笔记。

还要考虑这个用户有没有权限看这篇笔记。

成功以后返回笔记的信息，比如：

~~~json
{
  "id": 1,
  "title": "My Note",
  "content": "...",
  "authorId": 10
}
~~~

如果笔记不存在返回 404。

如果没有权限可以返回 403。

所以设计一个 API 不只是写一个方法，还要把路径、请求方法、输入、输出、权限和错误情况这些一起想清楚。

---

## 3. JSON

JSON 本质上就是一种文本格式。

比如一个用户可以写成：

~~~json
{
  "id": 1,
  "name": "zookie",
  "age": 20
}
~~~

因为最后传的是一种固定格式的文本，所以 Java、JavaScript、Python 这些不同语言都可以处理。

Java 对象和 JSON 之间转换可以用 Jackson。

Spring Boot 里很多时候已经自动做了。

比如 Controller 返回一个 Java 对象，Spring 可以直接把它转成 JSON 再发给前端。

## 4. HTTPS

HTTPS 可以理解成 HTTP 外面加了 TLS。

建立连接的时候，服务器会把证书发给客户端。

客户端会检查这个证书是不是可信，以及证书是不是当前这个网站的。

然后双方通过 TLS 握手协商出后面通信需要的密钥。

真正大量传输数据的时候主要用对称加密，因为速度更快。

证书和非对称密码主要用来解决身份验证、安全协商密钥这些问题。

所以后面传登录密码、Cookie、请求内容的时候，就不是直接明文在网络里跑了。
